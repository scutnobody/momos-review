# MOMOS 工业设计评审台

上传产品图片，查看三维评分及图片部位上的专家论点。首页附带 ARC 01 台灯示例，演示证据引用和撤回评分。

## 本地启动

需要 Node.js 22+、Python 和 Pillow。Windows 在项目目录执行：

```powershell
python -m pip install -r requirements.txt
node server.mjs
```

访问 http://127.0.0.1:4173 。默认仅监听本机。macOS 或 Linux 默认使用 `python3`，可用 `MOMOS_PYTHON` 指定 Python 路径。

复制 `.env.example` 到 `.env`，配置支持多张图像和 JSON 输出的 Chat Completions 服务及评分、Agent 两个模型 ID。评分模型独立负责所有子项给分和改分。可选的 `MOMOS_LOCATOR_MODEL`、`MOMOS_LOCATOR_BASE_URL`、`MOMOS_LOCATOR_API_KEY` 用于部位定位。默认使用 Agent 模型和端点，仍单独发起定位请求。设置独立定位地址时，请按需填写定位专用密钥。可按角色覆盖接口地址和密钥，地址填服务的版本路径，省略末尾的 `/chat/completions`。配置后重启。

## 路线 A

- 在「建立设计」页添加主图和草稿参考文件，可补充项目名、设计说明、设计目标、参数和测试结果。点击图片卡片可切换主图，参考图和 PDF 留在当前页面。评审重点和所选 Agent 视角用于加强对应专家的解释，评分量表保持完整。

- 初评分和部位定位并行。初评分只使用原图，复评可引用对应图像裁切，定位 Agent 只返回可见部位的名称、矩形框和关联维度。后端生成裁切供专家解释、审核及相应子项复核。无可靠部位或定位服务异常时，仍生成整体评审，界面说明未显示热点的原因。

- 采用专家评分表的 MOMOS V4 量表。形式与美学 3 项、功能与使用 4 项、安全与实现 3 项，分别使用 A1–A3、F1–F4、S1–S3。逐项使用 1–5 分锚点，图像证据不足记为 N/A。维度分由已发布子项等权平均，四舍五入到一位小数，界面同时显示覆盖数。旧报告保留原评分量表。
- 三类专家分别解释设计、使用体验和安全实现。每条论点绑定子项、评分及可追溯证据。设计说明和测试结果按非空行编号，参数按字段编号，图像区域按部位编号。
- 审核 Agent 逐条核对评分依据和论点，给出有支持、与证据矛盾或信息不足及理由。后端还检查引用是否存在，以及特定子项的证据类型要求。用户输入的测试数据标明由用户提供。
- 审核未通过的子项交原评分模型复核，未通过的论点交回原专家修订，复核后再逐条审核一次。二审仍未通过的评分暂缓发布，论点从发布结果撤回，原文保留在修订记录中。
- 点击标注可看部位论点、证据裁切及复核记录。维度评分中可展开子项和量表，结果可导出为 JSON。每次成功评审会在 `.reviews/` 中留存相同的 JSON，可通过 `MOMOS_REVIEW_DIR` 改存储位置。

评审时，图片、裁切及填写的资料会发给已配置的模型服务。服务器留档包含文本资料、坐标及上传图的 SHA-256，不包含图片像素。

## 评审问答

完成一次评审后，可回到「建立设计」页的「整机 Agent 问答」，或在结果页的标注详情中点击「问这个部位」。问答默认沿用 Agent 模型配置，也可通过 `MOMOS_CHAT_BASE_URL`、`MOMOS_CHAT_API_KEY` 和 `MOMOS_CHAT_MODEL` 配置专用文本模型。问答基于已发布的评分、专家论点和证据来源回答，也可结合初审和二审记录解释改分或撤回原因。回复中的证据引用可展开查看。每个部位和整机各自保留本页对话，发送时仅提交所选范围的最近六轮记录；对话不写入评审文件。问答时不会再次上传原始图片。切换到另一份评审或刷新页面会清空对话。

## 验证

运行 `node --test`。测试使用本地受控模型替身，并调用真实的 HTTP 接口和 Pillow 裁切，不使用外部模型额度。
